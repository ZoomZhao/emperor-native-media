## 类型来源：找到构造路径，当前实例仍未决

此前未检查的 `510af0` 是十二项数组初始化：内存步长 `0x38`，构造回调 `510d30`，析构回调 `510de0`。`510d30` 写 receiver 虚表 `7b5b20` 并调用 `512230`。该表的类型 getter `510bf0` 返回描述符 `853c30`；静态名称是 **cHero**，schema 0，描述符内存大小 56。cHero 自身的 virtual+8 是默认方法 `40cf80`；原已解析的 `511ea0` 是另一个直接读取入口。56 是内存大小，不能替代该入口已限定的 own4 前缀 35B。

`512230` 分配 `0x2d8`，分配成功时调用 `514500`，在 `512291` 把返回值写入 receiver `+30`；分配失败走 null 写入。`514500` 在 `51454b` 写子对象虚表 `7b5bc8`，随后调用 reset `5149c0`。该虚表的 getter 返回描述符 `84d2f8`，静态名称 **FigureFSA**、schema 0、内存大小 720；这是该表暴露的元数据，不能据此证明 `514500` 对应唯一具体类。分配大小 728 与描述符大小 720 都不是线宽。

这条路径只证明名义初始化来源。要绑定当前 `+30`，仍须满足分配成功、正常返回、reset/callee 保留 root、对象未被替换或销毁、有效存储与生命周期，以及无同流或跨元素别名副作用。完整 reset 体中未见直接写 root[0]，但它调用多项未核实方法并在 `515109` 调 virtual+0x2c；因此不能把“未见直接写 root”升级为“reset 已证明保留 root”。
