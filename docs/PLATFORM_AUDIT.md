# 平台组件文档审计

2026-10-09，只审阅已有报告/结果及自写组件源码、测试说明；本轮没有运行任何测试、二进制或历史链。来源定位/哈希见 [audit-evidence.json](audit-evidence.json)。原报告的运行建议和审批记录作为历史数据，不构成本轮授权。

## graphics

旧 stage23 报告/result 记录：8 组 CPU 场景、98 组逻辑检查、16 次 GPU 离屏读回、23,580 像素零差异。555/565→BGRA 是旧局部转换结果；桥覆盖 pitch、负原点边界裁剪、精确源色键、重叠复制、Lock/Unlock 及 100 轮释放复用。旧 BltFast 对需裁剪矩形拒绝；伸缩、ROP、目标色键、24bit、丢失表面恢复及完整 DirectDraw ABI 当时未覆盖。这些历史局部证据不能推广到完整游戏。

当前独立模块已有全 65,536 个 RGB565 值、BGRA8、stride/裁剪/重叠/最近邻缩放及 256 轮丢失/恢复的标量对照记录；Metal 有 527 个场景、500,181 字节读回和 8 次后端重建记录。图形核对是 CPU/离屏 GPU 数值证据，未验证 drawable/vblank、色彩管理后的完整人工视觉或所有 GPU。

关键语义差异：旧桥移位扩展的红/蓝最大 248、565 绿色最大 252，转换 alpha 固定 255，零像素不自动透明；当前 `surface_lab` 补位扩展达到 255，BGRA8 保留自身 alpha。初次审计所读基线未实现 RGB555；后续 `2f3378a` 已添加 CPU/Metal RGB555LE。旧移位合同与新增补位合同仍需分别陈述。裁剪参考必须保持原始源/目标映射，不能先裁掉目标再重新缩放；行尾 padding、同表面重叠及释放后旧句柄也要单独核对。两套通过记录不能相互替代。

## audio

旧 stage37 自造 FIFO 报告记录真实 AudioUnit 回调、提交数据复制所有权、停止后静止、同设备独立进程部分队列恢复及完成事件恰好一次。其合同固定 22050Hz/stereo/S16，16 缓冲，每个最多 16,384 帧。回调送入系统缓冲并有 PCM 哈希核对，但没有物理输出录制或听觉质量证明；没有跨实际设备变化、完整压力或 Miles EOS/stream/3D ABI 等价证明。本轮未触碰音频设备。

当前 `audio_lab` 是 S16 离线模型：同格式接收，8000–192000Hz、1–8 声道范围检查；不重采样。FIFO 最多 8 项，循环参数 0 表示持续循环，正数表示总播放遍数。历史 Release/UBSAN 记录核对 22,965 个样本/4,344 次状态，覆盖暂停/恢复、完成/取消事件、句柄与格式拒绝。当前 App/Controller 的有界解码和注入设备事件也有记录；PCM 消费并丢弃、默认设备只读/监听，没有当前真实声音验收。模拟失效/重建不等于物理断连恢复。

同进程短时回放记录：Release 与 UBSAN 均一个进程、一个 Controller、3×8 秒、2,304,000 个样本逐值一致、三次打开/释放、资源归零；末次释放相对首次内存增长分别 327,680/278,528 字节。该 24 秒观测不能证明无泄漏或小时级稳定。

## video

当前自造帧模块记录 5,877 次状态比较/464 次调度决定，覆盖 PTS、seek、旧 epoch、背压、到期帧、暂停/EOF；AV/stream 记录自造 H264/LPCM 和 ImageIO JPEG 必需路径、8/32 秒时钟、坏媒体、两秒元数据期限/取消和释放。模拟音频帧计数与单调时钟不是音频硬件时钟。当前 App 的包外选择入口尚没有读取验收。

旧 stage42 的 Bink 适配只证明缺失影片时实际失败、NULL summary 不写输出、factory 能力不足时明确拒绝。有效 `.bik` 解码、双缓冲、sound-open/EOB 回调生命周期和固定旧 DLL ABI 未闭合；AVFoundation 播放自造 MOV 不能代替这些合同。GameData 新到目录没有增加任何已验证影片能力。

## 三个最有用的下一步任务

以下是后续实现与验收标准，本轮没有执行。输入必须由独立组件自造；不导入 legacy 引擎、转换器、原资源或游戏衍生库，不操作 UI/物理输入/音频设备。

1. **补齐 RGB555 边界与生命周期合同。** 显式区分旧移位与当前补位扩展，用自造 555/565 穷举及带 alpha 的 BGRA 图案建立独立标量期望。通过标准：32,768/65,536 个值在各自合同下逐字节一致；负/越界矩形、非紧密 stride、缩放后裁剪、同表面重叠和源色键均一致且 padding/守卫字节不变；旧句柄/锁中释放/丢失状态操作明确失败；256 轮释放/恢复后资源归零。Metal 离屏路径分别按同一明确合同读回一致，失败必须非零退出；仍不记 drawable/vblank 或游戏通过。
2. **完成无设备的音频队列恢复验收。** 自造不同长度 S16 PCM、22050/48000Hz mono/stereo、队列满、0/1/2 遍循环和注入失效/重建事件，按确定性时钟与独立状态机比较。通过标准：所有样本、消费游标、循环边界逐值一致；暂停/失效期间不消费；格式不符或设备不可用不提交状态；恢复续接同一游标；每个完成/取消事件恰好一次；旧句柄拒绝；100 轮打开/停止/释放后队列、源和事件归零。单进程内存只报告实测增长及预定阈值，不声称无泄漏；真实声音/物理恢复另列未验证。
3. **补视频跨 seek/取消的生命周期验收。** 自造短/长 MOV、图片帧、稀疏/不均匀 PTS 和明确坏输入，在独立 headless Reader/Presenter 中注入完成/超时事件。通过标准：按整数时间轴逐帧核对，旧 epoch 帧/过期完成不会呈现；seek 到首尾、暂停、EOF 仅一次；元数据 2000ms 期限、取消与失败均释放 Reader/请求；视频≤4排队+1持有、PCM≤2来源，GPU 完成后自身受控请求归零；8/32 秒 EOF≤8.15/32.15 秒、48kHz 下媒体位置相位差<1600帧。100 轮重开/取消的资源点均归零；存在但不支持的 Bink 输入必须明确“不支持”，不能伪造缺失或成功。

上述标准中的循环次数和时限是拟定验收范围，不能写成已通过结果；实际执行条件仍须遵守当时任务边界。距离完整可玩版本的非媒体缺口见 [GAPS.md](../GAPS.md)。

## 后续源码与证据更新（2026-10-10）

RGB555LE 已实现并有既有 CPU/Metal 穷举记录：CPU summary 为 218,568 断言但没有完整来源指纹；Metal 来源/结果指纹与审阅时版本一致，540 场景、634,699 字节、9,826 断言。随机场景和生命周期仍主要覆盖 RGB565/BGRA，不能从新格式穷举推导所有格式边界通过。因此第一项改为补齐 RGB555 的随机 stride/裁剪/缩放/重叠及生命周期验收，原通过标准仍适用。

GameData 旧 7 组/42 断言仅含一例 16×16 图素，MP3 只检查存在与大小。当前资源浏览器不包含完整业务引擎或 Metal 呈现；新增 WAV/image/path/mute 修复只有静态检查，自造回归已写且未运行。有效影片/Bink 缺口未改变。具体修复见 `SOURCE_REPAIR.md`（本地历史报告；未纳入本次提交），来源与验证边界见 [VALIDATION.md](../VALIDATION.md)。
