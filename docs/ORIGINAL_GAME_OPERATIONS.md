# 原版游戏操作、存档副本与本地采集

本页记录已在本机成功使用的 **Windows 原版 1.0.1.0 + 既有 Wine 包装**流程，供人工操作和受监督采集复用。它与仓库的原生 `EmperorApp.app` 不同；`.sav`、原生 `.encity`、原版世界 `.emworld` 也不能混用。本文不是新实验的执行指令，项目暂停时不要据此恢复游戏、编辑器或逻辑开发。

最初整理本页时只读取已有脚本、记录和历史截图，没有重新启动游戏或采集新截图。成功依据是 2026-10-23 的正常保存/重载和 2026-10-29 的同进程暂停双存档；自动控制器的离线测试不计为原版操作成功。细节见 [SAV 保存/重载记录](SAV.md#original-gui-savereload-evidence-2026-10-23) 和 [手动暂停双存档](SAV.md#supervised-manual-paused-snapshot-pair-2026-10-29)。

## 1. 本机位置与环境

以下位置在 2026-10-31 文档整理时已只读确认存在。`$HOME` 表示当前用户主目录，其他机器须核实自己的路径；本页不附带这些文件。

| 用途 | 本机位置 | 使用原则 |
|---|---|---|
| 已安装的原版 macOS 包装 | `/Applications/皇帝龙之崛起.app` | 保持原安装不变 |
| 包装内既有 Wine | `/Applications/皇帝龙之崛起.app/Contents/SharedSupport/wine` | 不另装 Wine，不替换引擎 |
| 用户自备原始数据根 | `$HOME/Workspace/lzjq/GameData` | 含原始资源和 `Save/`；工具只读 |
| 既有隔离测试根 | `$HOME/Documents/Codex/2026-10-23/task/original-blackbox-20261023` | 下文记为 `ISOLATED` |
| 可写的游戏工作副本 | `$ISOLATED/Game-ddraw` | 新测试存档仅写这里，不能覆盖旧档 |
| 独立 Wine 环境 | `$ISOLATED/WinePrefix` | 不使用或清理用户默认 Wine prefix |
| 隔离启动器 | `$ISOLATED/native-launcher/Emperor Test Launcher.app` | 本地自编工具，不随仓库分发 |

可在当前终端设置局部变量，路径含空格时始终加引号：

```sh
ISOLATED="$HOME/Documents/Codex/2026-10-23/task/original-blackbox-20261023"
DATA_ROOT="$HOME/Workspace/lzjq/GameData"
```

原生 App/仓库解析工具通过 `--data-root` 或**单次进程的** `EMPEROR_GAMEDATA_ROOT` 使用原始数据；不要修改 shell 启动文件或全局环境。这个变量**不是原版 Wine 游戏的启动参数**。隔离启动器实际使用独立 `WINEPREFIX`，工作目录为 `Game-ddraw`，执行既有 `wine32on64 Emperor.exe`。本页不提供绕过启动器的直接 Wine 命令。

## 2. 保护原件与准备副本

先关闭相关测试实例，再清点需要保护的原始资源、`Save/`、配置和已验收 App。把清单及 SHA-256 保存在仓库外的私人任务目录；本轮结束与开始时比较同一清单。开始时已经缺失的文件单独记录，不能把它们算成“本轮删除”或“保护通过”。

- 原始 `GameData`、安装包、已有用户存档和已验收 App 始终保留。不要将测试另存路径指回原件。
- 独立副本必须是真正复制的文件/目录，不能用 Finder 替身、符号链接或硬链接冒充隔离。复制前检查目标不存在；复制后核对内容及不同文件身份。
- 游戏工作副本与 Wine prefix 必须保持既有隔离布局。当前启动器只接纳固定的 `ISOLATED` 根，不能把 `Game-ddraw` 本身、任意新目录或原安装当作该根。复制出一个备份不等于它可直接启动。
- 完整备份还应保留需要的配置/独立 prefix 状态；不要边运行边复制作为一致性快照。备份放在仓库之外的新目录，不合并覆盖旧备份。

已存在的原始用户样本位于 `$DATA_ROOT/Save/zoom/` 和 `$DATA_ROOT/Save/项羽/`。隔离测试主要使用：

| 隔离副本内相对位置 | 既有用途 |
|---|---|
| `Save/2026102301/` | 早期教程、保存重载及 `320110/320111/320112.sav` 等采样 |
| `Save/2026102801/280001.sav` 至 `280016.sav` | 原有有限数字采集范围，不表示这些文件都存在或仍可写 |
| `Save/2026102802/281001.sav` 至 `281032.sav` | 食品链观察的有限范围；其中已有许多档，必须逐一查重 |

`281004.sav` 和 `281005.sav` 是已成功的暂停双存档证据，必须保留，**不是可复用的新名字**。名称范围是采集器的应用级清单，不是系统许可，也不保证有空闲名字。若范围已用完，停止，不擅自改名越过清单。

若需要把一个原始 SAV 复制到**已存在的测试玩家目录**，下面是只写一个新文件的文件级做法；先将占位路径换成明确目标。本例不是本轮已执行命令，也不保证任意旧档都能被原版或采集器接受：

```sh
SOURCE_SAV="$DATA_ROOT/Save/zoom/历史战役自动存档_2.sav" \
TARGET_SAV="$ISOLATED/Game-ddraw/Save/<已存在测试玩家>/<全新名字>.sav" \
python3 - <<'PY'
import hashlib, os, shutil
from pathlib import Path
src = Path(os.environ['SOURCE_SAV'])
dst = Path(os.environ['TARGET_SAV'])
if src.is_symlink() or not src.is_file() or not dst.parent.is_dir():
    raise SystemExit('先核实原文件和已存在的测试玩家目录')
if dst.exists() or dst.is_symlink():
    raise SystemExit('目标已存在：保留旧档，换一个明确的新名字')
before = hashlib.sha256(src.read_bytes()).digest()
with src.open('rb') as reader, dst.open('xb') as writer:
    shutil.copyfileobj(reader, writer)
if hashlib.sha256(src.read_bytes()).digest() != before:
    raise SystemExit('原件在复制期间变化：停止；保留副本供排查')
if hashlib.sha256(dst.read_bytes()).digest() != before:
    raise SystemExit('副本不一致：停止；不要把它作为合格起点')
a, b = src.stat(), dst.stat()
if (a.st_dev, a.st_ino) == (b.st_dev, b.st_ino) or b.st_nlink != 1:
    raise SystemExit('副本身份不独立：停止')
print('新副本内容一致且身份独立；原件未改写')
PY
```

恢复优先用原版正常读档菜单选保留的旧快照，再以全新名字继续；不要把旧文件拷回覆盖当前测试档。需要回退整套环境时，先退出本轮进程，保留失败工作副本，再从备份复制到新目录；当前冻结启动器对新根的支持未经验证，不能直接挪目录或改其路径策略冒充已恢复。

## 3. 启动与进入城市

已验证的正常入口：

```sh
open "$ISOLATED/native-launcher/Emperor Test Launcher.app"
```

1. 检查没有属于另一轮的启动器/游戏实例。记录本轮启动时间和后续实际 PID、可执行路径、开始时间、父子关系及窗口，不沿用旧日志里的 PID。
2. 在启动器点 **选择测试目录…**，用正常 macOS 目录选择框选 `ISOLATED` 根，不能选其下的 `Game-ddraw`。核实选择器当前目录和可见按钮后确认，不盲打路径或坐标。
3. 等待启动器确认宿主及子进程目录读写检查通过，**启动独立游戏**按钮可用后再点一次。启动器不能用 CLI `--root` 预选目录；访问未通过就停止，不伪造书签、不改变系统权限。
4. 在游戏正常菜单进入单人游戏，选明确的测试玩家，再进入读档列表，核对名字和选中态后载入。首次教程曾经验证过新建测试玩家、进入夏朝首个教程并关闭提示框；它不是任意场景都已验收的保证。
5. 每次载入后重新核对城市、日期、资金和人口。读档会消耗时间，而且已有实证表明：保存时暂停的档，重载后可能恢复运行。磁盘档的状态不能直接当成当前活跃状态。

启动器会检查既有 Wine 进程及会话锁；拒绝时不能删除锁或终止其他 Wine 来硬启动。其源码在本地 `native-launcher/main.mm`、`policy.hpp` 和 `access_probe.mm`，不是原版程序源码；`build.py` 的早期构建报告也不能替代后续真实界面验收。其他电脑的引擎、窗口尺寸、目录授权未验证。

## 4. 暂停、速度与输入

**以界面反馈为准，不以“按键调用成功”为准。** 已验证的闭菜单明确暂停横幅是“游戏暂停（按 P 键继续）”。

- 已有横幅时不要再按暂停切换键。没有横幅也不能单独证明正在运行；可用当下真实日期推进作运行证据，不能用草木动画或打开菜单推断。
- 原版的 P 是暂停/继续切换；Space 不是本项目已验证的暂停方式。文件菜单打开时会自动停时，且可隐藏横幅；这不等于关闭菜单后仍明确暂停。
- 本机成功的受监督事件路径是临时选已启用的 **ABC**，目标游戏在前台、无菜单/弹窗/用户输入争用时，用 `HIDSystemState → kCGHIDEventTap` 发送一次键码 35 + Shift、约 250ms 后释放，然后看横幅。这是本环境的成功输入记录，不是跨机器通用按键规范。
- 之前只向 PID 投递 P 的路径未取得暂停反馈，不应照搬为成功方法。完成本轮自发事件后，在同一 HID 流释放 P 和左右 Shift；只清 modifier flags 或换用 PID-only Up 不能证明实体键已释放。不要强行释放用户原本按住的键。
- 记录并恢复原输入源。本机历史原输入源为双拼；不能把 ABC 当永久设置。鼠标按下事件也必须配对抬起。
- 正常 **选项 → 速度设置** 中已实读游戏速度 80%、卷屏速度 60%；曾临时把游戏速度改为 20%并在结束前恢复。它们是两个不同控件，改动时逐次看清实际值，不猜 0 的含义、不假定倍率线性或每秒阶段上界。

## 5. 正常保存、读取与暂停双快照

历史保存画面中的实际菜单名是 **文件 → 存储游戏**；对话框下方是 **取消 / 好**，不是原生 App 的 `.encity` 选择器。

1. 先确认明确暂停。在打开存档菜单前，预查目标 `Game-ddraw/Save/<测试玩家>/<新名字>.sav` 不存在，也不是悬空链接。
2. 打开 **存储游戏**，先看当前文本。默认框可能仍填着已存在的 `281001` 等旧名字；不能直接点“好”。选中并完整替换为新数字名。
3. 用新鲜截图逐字核对目标名、当前玩家与对话框。提交前再查文件不存在，然后正常点一次 **好**。未知覆盖警告不确认。
4. 若调用超时或结果不明，先查实际文件和当前画面，不重复按确认。只有目标普通文件已生成、大小/身份稳定且独立解析成功，才能记录保存通过。
5. 读取走正常读档菜单，核对文件名后载入；随后重新确认暂停。不要把 `.sav` 交给原生 `.encity` / `.emworld` 消费者，也不假设编辑器能加载它。

证明“闭菜单暂停期间时钟不变”需要**同一进程、同一次会话**的两份正常新保存：第一份保存后关闭菜单，看明确暂停横幅，等待，再保存第二份，中间不重载、不恢复运行、不再切换 P。至少比较不同文件身份、cycle/phase/month-part/month、年份及非时钟状态；完整字节相同是更强的对照。文件复制不能当作第二次游戏保存，不同会话两档不能拼成暂停证明。

2026-10-29 的人工双存档已实证闭菜单等待约 149 秒、两新文件身份不同且完整内容相同，并完成正常退出/输入恢复。它不认证旧自动保存消费者、日历/食品算法或安全运行阶段上界。旧自动控制曾因整屏像素、OCR/字形和菜单契约误拒绝而失败；对清晰可见的正常保存框采用新鲜截图人工核验，不需要为其额外重建逐像素模板。系统真实拒绝和禁止覆盖原件的边界仍然有效。

### 同进程时间推进快照：做法与限制

比较后续运行时，先确认明确暂停并保存新档；确认窗口、焦点和当前画面后恢复运行，记录事件与日期，再次确认暂停并保存另一个新档。保存前每次检查目标不存在且不是符号链接；在正常保存框逐键清空并输入新名字，截图核对后只确认一次，随后核验文件大小、哈希稳定及暂停横幅。逐键输入的按下和抬起必须配对，结束后检查自发按键已释放，避免未验证的全选组合留下修饰键。普通剧情操作按本轮授权逐项记录；遇不明弹窗或窗口状态先停止。

P 是状态切换，须回读实际暂停横幅；脚本曾设的 45 秒阈值及整帧像素相等并非平台要求。图像匹配曾将暂停横幅误判为弹窗，也不能单独证明没有未知弹窗。

2026-11-02 的城市 B `280008`、`280009` 是同一隔离进程中的正常新存档，分别在公元前 1603 年 9 月和 10 月明确暂停后保存，资金 1257→1197、人口 572→572。SHA-256 分别为 `3c423715491bf938863f2ed3fca38b8f829334449029b730eade201fede4b44d` 和 `2724680ff595ce4d7c5d9e18b59d1f9a9f3e3ca5a0631dfd186f45e0eb0764d7`。第一次暂停发生在载入一段时间之后，不是载入瞬间；接见使者和接受 786 钱礼物均在 `280008` 之前。两档之间发生物资要求未满足及评价下降提示，均由玩家记录并关闭；跨月不证明恰好经过完整一月。资金减少 60 不能归因于礼物。

只读比较中 568 个活动建筑身份及 205 个道路单元集合一致，不能推广为全部地形或游戏状态一致。导出器的建筑输入及人物池不完整，完整存档字段契约未通过；该时间推进样本不是上一段所述的闭菜单暂停不变性证明。OpenCode 独立复核因 502 中断，尚未完成；城市 A 的 `280005` 仍待采集，`280006` 是更早的一年样本目标，不属于当前最小清单。原始存档、截图和私人记录留在仓库外；正常退出后核验既有数据并记录配置变化，不擅自还原。

## 6. 截图与只读导出

每次重要动作前后采集**当前目标窗口**，记录时间、PID/窗口 ID、窗口边界、输入源、可见菜单/暂停状态及相应新 SAV 名。截图可能有缩放，不能把旧 PNG 像素坐标当成本次点击坐标。保存对话框的文字和文件实际生成结果要分别记录。

已使用的本地只读截图入口是 `/tmp/original-control-20261028/probe.py`。以下只适用于该历史工具仍存在、依赖和原有屏幕读取能力均可用、且当前进程身份匹配时；不要为了复现文档安装依赖或改系统权限：

```sh
CONTROL=/tmp/original-control-20261028
# GAME_PID / LAUNCHER_PID 必须取本轮实际身份，不能照抄历史数值。
python3 -B "$CONTROL/probe.py" "$GAME_PID" "$LAUNCHER_PID"
```

它只读目标身份/窗口和当前输入源，不聚焦、不发输入、不启动游戏。输出 JSON 的 `local_capture_directory` 指向新建的 `probe-<唯一编号>/`，PNG 是其中的 `capture-<时间编号>.png`；`frame.image` 给出文件名。它会核对启动器路径、父子关系和唯一游戏窗口；拒绝时保留原因，不改成任意 PID 截屏。该临时脚本并非仓库公开工具，目录不存在时不能假称命令可用。

本地历史产物位置：

- 成功暂停双存档：`/tmp/original-control-20261028/manual-pair15-20261029T073119Z/`，含历史 PNG、`timeline.jsonl`、`pair-result.json` 和独立复核。
- 其他食品链采集：同级 `market-*` 目录，具体档名以各轮时间线为准，不假定所有阶段都被捕获。
- `/tmp` 可被清理。需要长期保留时，将整轮私人证据复制到仓库外的新归档目录并核对清单；不要只保留会失效的 PNG 路径。

仓库中的数值导出器可只读复核明确清单内的 SAV；下面命令会编译/测试导出器并在新的仓库外目录写报告，**不操作游戏**。目标档必须真实存在，`--output-dir` 也必须是尚不存在的绝对路径：

```sh
EMPEROR_GAMEDATA_ROOT="$ISOLATED/Game-ddraw" \
python3 -B scripts/original_evidence.py --scope food-chain \
  --source 'Save/2026102802/281004.sav' \
  --output-dir '/absolute/private/new-evidence-directory'
```

参数和精确路径清单以 [脚本](../scripts/original_evidence.py) 为准。`--check-capture-targets` 只检查有限范围缺席，不创建存档或给予实验授权；已有历史档时失败是正常保护。遇未知类、未知 FSA 或未完成 actor 池就停止相关认证，不能跳过未知结构继续宣称库存或“没有某行人”可靠。更多字段边界见 [SAV](SAV.md) 与 [行人格式](SAV_FIGURES.md)。

原版资源、原始/测试 SAV、截图、逐文件指纹清单、派生像素和私人日志均留在仓库外；不发给外部模型，也不随文档提交。仓库 `.gitignore` 只是辅助，不能代替逐文件检查。

## 7. 正常退出、恢复和故障收尾

1. 停止新增操作，确认当前状态；只在允许范围内保存一个新终态，来不及时优先正常退出。准备、截图往返、保存和退出都计入同一预算，不重开目录重置时钟。
2. 正常走 **文件 → 退出游戏**，看清退出确认框后确认。未知弹窗先核实；不反复盲点，也不把“发出了退出”当成已退出。
3. 核实本轮游戏目标已消失，再等待启动器显示 **本次隔离实例已结束。再次测试需重新选择目录。**，然后正常 Cmd+Q 退出启动器。**游戏还活着时不要用启动器退出/“停止本次测试”代替正常游戏退出**：该启动器的清理包含仅针对其独立 prefix 的 `wineserver -k`。
