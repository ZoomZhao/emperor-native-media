# 原生媒体能力与下一步验收

2026-10-11；审阅基线 `3a15dc7b8c4b96e55da975210a86f0c1bedd2497`。本轮只核对已有报告、结果和自写音频接口；没有重新编译、运行测试、操作窗口或音频设备，也没有读取 EXE、反汇编、GameData、旧 Swift，或分析城市逻辑。历史报告中的命令和批准记录不是本轮执行授权。

结论：三个平台组件已有局部数值和状态证据；完整声音、物理设备恢复、有效 Bink 与原游戏兼容仍未闭合。GameData 放入目录不增加验收证据。来源摘要与 SHA-256 见 [证据索引](native-media-capability-audit.json)，详细历史边界见 [平台审计](PLATFORM_AUDIT.md) 与 [验收摘要](../VALIDATION.md)。

| 能力 | 已有证据与不能推导的结论 |
|---|---|
| graphics 像素格式 | 旧 stage23：555/565→BGRA，8 组 CPU 场景、16 次 GPU 读回、23,580 像素零差。旧移位扩展的红/蓝最大 248、565 绿最大 252，alpha 固定 255，零值不自动透明。当前组件采用补位扩展至 255，BGRA 保留自身 alpha；RGB555LE 后续有 32,768 色值记录。两种颜色合同不可混用。CPU RGB555 摘要缺完整来源指纹；不能视为当前所有路径通过。 |
| graphics 裁剪、缩放、生命周期 | 当前 RGB565/BGRA 的独立标量对照覆盖非紧密 stride、负原点、裁剪、重叠、最近邻缩放及 256 轮释放/恢复。RGB555 后续 Metal 记录为 540 场景、634,699 字节读回，但随机组合和生命周期覆盖不能自动从格式穷举推出。裁剪须保留原始映射，检查 padding、旧句柄和丢失状态；离屏读回不证明 drawable/vblank、完整视觉或游戏通过。旧桥的 BltFast 裁剪拒绝、伸缩/ROP/目标色键/24bit/完整 DirectDraw ABI 缺口仍属旧桥边界。 |
| audio 队列、循环、格式 | 当前自写 Player 是离线 S16 队列，最多 8 项；0 表示持续循环，正数为总播放遍数。合法配置为 8000–192000Hz、1–8 声道，来源必须与播放器格式相同，不重采样。既有 Release/UBSAN 各核对 22,965 个样本、4,344 次状态；覆盖复制所有权、跨缓冲、循环、暂停、完成/取消事件及代际句柄。失败与恢复证据只适用于对应冻结版本。 |
| audio 设备恢复与声音 | 旧 stage37 固定 22050Hz/stereo/S16、16 缓冲，实际 AudioUnit 回调及同一设备上的独立进程部分队列恢复有记录；当前 Player 的丢失/重建是注入状态事件。两者均没有物理输出录制、听觉质量、硬件时钟或真实设备断连恢复证明。App 静默影片消费 PCM 后丢弃；离线解码和 PCM 哈希不能算听觉验收。 |
| video 调度、消费者与缺口 | 原始帧模块有 5,877 次状态比较、464 次决定，覆盖整数 PTS、seek、epoch、背压和 EOF；自造 H264/LPCM、JPEG 及 8/32 秒集成有对应记录。当前 MovieSession 已有异步换片/关闭、取消和错误交付的独立消费器记录；固定首帧 64×48、连续帧 32×24/stride133，不能推出任意布局支持。后续窗口报告记录了有限静默播放、暂停、seek、清空和正常退出；不能沿用旧“完全未运行 GUI”的总括说法，也不能推导完整 EOF、全部尺寸或声音通过。 |

Bink 旧报告只证明缺失输入真实失败、NULL summary 不写输出、factory 缺能力明确拒绝；没有有效 `.bik` 解码、sound-open、双缓冲/EOB 生命周期或固定 DLL ABI 等价证据。自造 MOV 的 AVFoundation 路径不能替代它。模拟音频帧计数和单调 HostClock 也不能替代硬件音频时钟。[影片异步合同](APP_MOVIE_ASYNC.md)、[退出合同](APP_TERMINATION.md) 和 [有限窗口结果](WINDOW_ACCEPTANCE.md) 各有版本与范围，不能互相代替。

**三个最有用的工程任务。** 以下是建议实现和未来通过标准，本轮未执行，不作为新增通过数字。均消费现有生产组件，只用完全自造图片、PCM、MOV 与可控事件；不接回历史执行链。

1. **补 RGB555 的组合边界与来源绑定。** 用独立算术标量期望覆盖全部 65,536 个字值（含高位别名），以及 RGB555/RGB565/BGRA 的奇数 stride、alpha、四边裁剪、缩放后裁剪和同表面重叠。通过标准：CPU 与离屏 Metal 分别逐字节匹配各自明确颜色合同；padding/守卫不变，错误操作不改活状态，旧句柄拒绝；256 轮释放/丢失/恢复后受控资源归零。保存源码、输入、产物、结果指纹；缺 Metal 能力必须报未验收。旧移位合同只作历史说明，不运行旧转换代码。
2. **接通可替换的离线 PCM 与恢复事件消费者。** 在现有媒体消费者上注入 fake sink/设备事件，使用不同长度的 mono/stereo S16、22050/48000Hz、队列满及 0/1/2 遍循环。通过标准：样本、游标、循环边界与独立状态机一致；暂停/失效不消费，格式错误/不可用恢复不提交状态；成功恢复续接原游标，重复和旧代际事件不重复重建，完成/取消恰好一次；100 轮停止/释放后队列、来源及已领取事件归零。默认静音不请求真实输出工厂；仍不宣称听觉或硬件恢复通过。
3. **闭合 MovieSession 跨取消与关闭的失败恢复矩阵。** 复用现有 Reader/Controller/Presenter，组合自造短/长 MOV、坏输入、慢完成、seek、取消、坏替换与关闭失败重试，覆盖实际消费接口。通过标准：500ms 可控 worker 阻塞时 owner 请求在 100ms 内返回；只呈现最新 generation/epoch 的帧和错误；active/pending/main delivery 各≤1，视频≤4排队+1持有、PCM≤2来源；元数据 2000ms 期限与取消可终结，关闭确认后受控请求/Reader/PCM/GPU 归零，失败保留原因并可重试。8/32秒正常路径 EOF≤8.15/32.15秒，48kHz 下相位差<1600帧；100轮重开/取消分批保存，每进程≤60秒。不把受控计数归零称为系统无泄漏。
