# FigureFSA 测试驱动来源修复

基线为 `c1c75e40f3da71746fa62f1f90305de90c40a4d4`。按独审交付应用补丁 `52d1030a2f73c5a5266ab586e6e653beaaa5d52b5410d7b5977c397583f70dea`，新增四份独立测试文件，修正缓存回引用驱动，并将相同机制应用于六类新对象驱动。三个生产头和原测试 C++ 保持原字节。

旧驱动把 `--dependency-root` 下的头文件 hash 当作编译来源，但带引号 include 优先查找当前头文件所在目录。后备根未参与编译时，报告可能指向未编译的文件。修复保留既有搜索顺序，把该参数明确记录为请求的后备根；通过 `-MMD -MF` 保存 Clang depfile，逐模式记录实际选择的依赖路径与 SHA，汇总来源也来自实际依赖。此变更修正真实记录，没有只改文案或强制另一份头。

在未改动的私有新 payload 快照中同样复现了问题：后备 Goal 和缓存头以 `#error` 开头，两模式仍各 22/0，旧 JSON 却记录这些后备文件。修复后的两个驱动面对同一冲突目录仍成功，因为实际选择的是邻近头；逐模式 depfile、报告与文件 SHA 完全一致，未把 sentinel 记录为已编译文件。输出目录包含空格，也核对了依赖转义路径。
