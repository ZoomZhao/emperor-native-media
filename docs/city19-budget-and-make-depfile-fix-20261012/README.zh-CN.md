## 初始追加预算

原入口只在新append时检查FSA追加≤1024；因此初始prefix1/cache1026或prefix6020/cache7045，虽然已追加1025项，仍能读完一个不追加的76字节NULL记录。总8192上限依然有效，问题是已声明的累计追加合同没有在入参实施。

独立最小复现：旧头下两模式各 **2通过/4失败**。1024边界通过，但1025拒绝及相关输出保留检查失败。旧独立共享链补丁在当前基线为 **5/3**：预算失败之外，两个负例仍用已在当前目录中的FigureFSAState作未知名称；原结果完整保留。集成时只把这两个自造负例改为同长目录外 `UnknownFSAType`，并在expectations中明确记录，不把该调整当作0736源链审查。

生产修复只有一个新增条件：在验证prefix范围后，拒绝初始 `cache.size()-prefix_entries>1024`。保留1024包容边界、原前缀数和所有cache编号，不重设prefix以清零累计量。修复后独立边界每模式6/0，独立共享链每模式8/0；错误发生在结果发布前，不改调用方cache或既有输出。

## Make转义而非shell语法

旧驱动在私有 `O'Brien` 源码路径下编译成功，然后以 `ValueError: No closing quotation` 退出；旧depfile与异常回执保留。独审补丁采用Clang `-MT figurefsa-test` 固定target，按Make规则保留引号、处理反斜杠转义并把 `$$` 还原为 `$`。没有把depfile当shell命令，也没有只改说明文字。

该修补应用到缓存、新对象、已采用独立缓存、共享前缀四个驱动，并同步到此前复制的FigureFSAState驱动。第五个驱动的解析函数用实际Clang depfile单独核对；没有因此开展0736原来源或真实条件实验。所有编译依赖路径存在，SHA逐模式匹配。真实源码及输出目录含空格、单／双引号、`#`、`$`，修补均能复跑。
