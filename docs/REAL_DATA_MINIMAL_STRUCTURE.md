DAT 在版本字之后通过 `480740` 取得对象，再在 `52f31d` 调用 `[vptr+8]` 并传入 archive。该消费者的类型、消费宽度和下一边界尚未闭合。因此没有跳过它去解释后面的四字节局部槽位、计数或对象。城市 version19 的 pool 位置同样不能套用到这两份流。

文件类型资格来自加载器链，扩展名只用于定位：字符串 `empireinfo.dat` 及其引用在 `434d30`，只读 open 后以 mode1、4096 创建 archive，再调用 `52f2c0(S,0)`。地图 `%s%s.map` 在 `43aa90/43aac0` 构造路径；对应路径经 `534510 -> 52e7c0(S,1,owner)`，或 `534660 -> 534780 -> 52e7c0(S,0,null)`。版本读取复用 `41fc10 -> 41fca0 -> 41fcb0` 的两字节源码；前置 `40cf80` 为 RET4。

地图 version2 的显式请求先读取版本，再读取两个四字节字段，进入后续消费者前累计十字节。上述边界按所选显式请求序列及普通无同流别名副作用前提给出，不补原始进程的辅助函数、实时游标、回调或 OS 成功证明。

可继续的三个独立工程任务：

1. **自造前缀字段验证器**：输入自造版本字及两个 U32，以已读 span 为边界；通过标准是合法 map-v2 正好解释十字节、dat-v1 只解释两字节，短字段和错误版本在解释前失败，未知用途字段不获得业务名称，额外尾部保持未解释。
2. **nullable N 统计消费者**：检查 JSON 消费者并区分 marker、已读长度、codec 内 tail 与容器 tail；通过标准是未知 header/marker、block limit、长度截断 N=null，完整 N 后的 payload 截断保留 N，失败不输出未消费尾部数值，15 个自造输入的双构建 52 例保持通过。
3. **验收失败闭环**：只在私有自造源码/fixture 副本注入错误审核许可、错误预期源 SHA、强制 codec 失败；通过标准是 `-O`/环境优化均在输入/编译前拒绝，普通模式故障不得报零失败，收据绑定执行源码和工具摘要，流程不遍历 GameData。
