# Bink video and native audio

Format fields use the public [FFmpeg demuxer](https://ffmpeg.org/doxygen/trunk/libavformat_2bink_8c_source.html); no original-game code. `BIK` plus revision is Bink1; `KB2` is separately rejected. Little-endian metadata gives frame count, dimensions, rational FPS, audio track count and per-track sample rate/channel flags. Bounds: dimensions ≤4096, frames ≤1,000,000, FPS ≤240, duration ≤24h, BGRA frame ≤8 MiB and declared/physical size agreement. Audio metadata is bounded to256 tracks and8–192kHz; native playback accepts exactly one mono/stereo track. Other layouts are errors, with no guessed mixing.

`BinkProcess` → video-only `MovieReader` and a separate PCM pipe → `BinkPreview`/`BinkAudio` → existing bounded `MovieSession` → AppKit/CoreGraphics and macOS Audio Queue Services. Both decoder children use the same owned-process launch/read/close code. Separate backpressured pipes prevent video output blocking audio reads. Direct argv, file/pipe protocols only, no shell/network/output files. FFmpeg8.0.1 arm64 remains a separately installed external dependency, locally GPLv3-or-later; no FFmpeg executable/library is bundled or linked. Absolute `EMPEROR_FFMPEG_PATH` overrides `/opt/homebrew/bin/ffmpeg`; missing dependency is an error, never an install. License notice remains in THIRD_PARTY_NOTICES.md.

The original track is BinkDCT,44,100Hz,stereo. FFmpeg emits signed16-bit interleaved PCM in its declared rate/channels; no resampling is requested for this corpus. Six fixed4,096-frame Audio Queue buffers plus one decode packet bound client PCM storage to114,688 bytes here. BGRA client frames remain ≤8MiB each. These are client allocation bounds, excluding FFmpeg and native audio-system internal memory/RSS. There is no whole-clip audio/video cache, temporary media file or derived-media export.

[Audio Queue current time](https://developer.apple.com/documentation/audiotoolbox/audioqueuegetcurrenttime(_:_:_:_:)) supplies the audio master sample clock. Video chooses the due frame from that clock; silent files retain the monotonic video timeline. Pause preserves queued buffers and freezes the displayed position; Start resumes the same queue. Native AudioQueue time estimates stepped back1,604 sample frames on the full-run resume, also reproduced independently with wholly authored silent PCM. During resume only, a ≤100ms backstep may hold the existing image until the unshifted native clock catches up, within250ms; no fitted time offset is added. Other regressions/discontinuities fail visibly and close. Seek recreates both streams at matching video/PCM origins. Shorter-than-video audio is rejected explicitly at drain, avoiding a frozen Playing state; this boundary is exercised with an authored protocol fixture, not counted as original-data progress.

PCM EOF requests asynchronous `AudioQueueStop(false)` and waits for `IsRunning=0`, rather than equating a reusable-buffer callback with sound completion.
