# 文本资源载入反馈与重试修复

当前App把文件不可读取、GB18030解码失败和没有非空行统一显示成“原版中文文本库（共0条、GB18030转码）”，导致用户无法判断加载是否成功，也没有修复文件后重新加载的入口。

本次在现有有界文本加载器增加 `TextLoadResult`：成功、不可读取/超限、解码/转码失败、空内容四种状态。只有完整转换成功才发布行列表，失败不返回旧行或已转换的部分行。`AppMedia::textWithStatus`将结果交给App；原vector API继续保留同样的有效/空列表行为。界面使用共享格式化函数显示失败原因，并增加“重新加载”。每次替换原行列表、清空筛选行并按当前搜索重新过滤，再刷新表格；用户可修复同名资源后重试。

基线固定 `5af02d010af3d19f995bd54ea354f2c9417f077b`。自造缺失、空文件、非法GB18030和空白文件在Release/UBSan各触发4个反馈反例，进程退出1。基线实际调用旧生产文本加载器，并使用从main.mm逐字提取的标题格式在Foundation中生成标签；没有执行AppKit视图或窗口。因此是旧加载/标签合同的复现，不是完整GUI验收。

修复后新 `text-feedback` 套件直接调用实际AppMedia、ResourceRoot和生产解码器：Release/UBSan各73项通过。覆盖实际中文GB18030转UTF-8及行裁剪、缺失/非法相对路径/超限/空白/损坏编码、有效前缀后坏编码不发布部分结果、成功后失败不带旧行、同一AppMedia和同一文件路径的6次修复重试、共享反馈文字更新，以及旧列表接口兼容。输入完全自造；fake音频工厂调用数为0，默认静音保持。

含实际界面接线的App编译、链接、打包与签名strict校验通过，来源清单绑定候选源码；未启动。实际按钮点击、窗口反馈和用户文件修改竞态仍未验收，没有注入系统内存分配失败，也没有给Foundation插桩。每个构建/测试子进程限60秒。命令、输入、源码、产物与结果哈希见[核验收据](text-resource-feedback-receipt.json)，完整文件在任务目录 `text-resource-feedback-20261012/`。

```sh
python3 scripts/independent_runner.py text-feedback --mode release --output /absolute/new-output
python3 scripts/independent_runner.py text-feedback --mode undefined --output /absolute/new-output
```
