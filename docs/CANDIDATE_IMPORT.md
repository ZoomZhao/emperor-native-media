# App 只读候选存档导入消费者

2026-10-13，基线 `8d58b964bb93bd09605bf9f13b7a0fef33551055`。新增“候选存档”页，将当前已有的有界帧读取和有限解析结果接到实际App。它只保留检查摘要，不接收城市对象、不写入文件、不恢复自写城市，也不把局部成功显示为城市载入完成。

## 接线与预算

原生文件选择器从用户明确配置的资源目录开始。开始换文件时立即清除旧摘要；取消后清除路径并禁用重试。已选择的文件即使失败仍可同路径重新检查，新的结果完整替换旧状态。

消费者使用只读/nonblocking/no-follow文件描述符，拒绝非普通文件，在物化前检查1 MiB输入上限；核对完整读取/EOF及前后文件身份、大小和mtime。然后移动输入给未修改的 `OwnedFramedReader`，复用已批准静态候选profile，单块36144字节、累计解码256 KiB、64块。解码只有完整帧序列End才发布候选摘要；任意后块错误均不发布先前的私有解码内容，已验证帧数只作为当前失败诊断。

仅调用既有 `walk_city19_housing_goals`，窗口16 KiB、单对象checkpoint，默认只支持既有HousingGoal子集。它从3355入口核对局部结构，不检查前缀或证明文件类型。未扩展类型、版本或源链，不使用FigureFSA/0736。五个读取器源文件、既有Goal头、profile与review gate指纹保持原样；批准profile/owned包装及其哈希已核对。

界面分别报告文件读取、帧消费/文件剩余、解码完成、局部范围、未核对前缀、剩余后缀、合计未解析解码字节、压缩帧内未解码尾部，以及不支持/失败/预算状态。对于自造样本：读取3415、解码3403、局部 `[3355,3399)` 共44字节、前缀3355、后缀4、合计未解析3359。不能把3399当已解析字节数，也不能省略前缀；最终始终显示“未载入城市；未写入或修改候选文件”。

## 验收

独立构造的输入使用单独拼写的既有marker和宽度，全部自造。Release/UBSan各67项通过：取消/换文件、读失败、未知头、raw/zlib和帧内tail、局部范围、未知类停点、局部版本失败、坏校验/截断/好块后坏块、单块/累计输出/块数/文件输入预算、修复同名文件重试及重复检查。程序直接调用新增控制器和当前生产提供者，不运行资格工具或旧游戏链。

实际App编译、链接、打包、签名strict校验通过，包内清单包含新增消费者和file_io依赖。实际GUI最终PID46249在原生选择器中选择自造文件，12个检查点通过：局部样本、成功后取消、换到短数据、不支持头、坏编码、未知类、局部解析失败、输入预算拒绝、预算后修复、连续3次重试、删除后读取失败和同路径再恢复。每次格式检查前后输入SHA相同；测试控制器有意删除/修复的是自己新建的文件。当前自写城市HUD前后完全相同，默认静音保持，未点击城市载入/保存。

初次路径导航辅助2次失败导致正确取消，另一文件行辅助因AX对象未保活失败一次，记录完整保留；不是产品解码通过或权限拒绝。修正辅助对象保活后在明确资源目录里正常选择文件行。初次PID45337和最终PID46249均正常退出，没有强杀、权限申请或设置修改。记录/源码/输入/产物/动作/窗口截图保留于本地任务 `candidate-import-20261013/`，索引和哈希见[收据](candidate-import-receipt.json)；截图、App包及输入不提交到Git。
